# PHASE 3: COST-GRID TERRAIN ENGINE, SLOPE/NO-GO OVERLAY & A* PATHFINDING

## A. Phase Objective
Replace the hardcoded static SVG route (`#route`) with a real 2D DEM/slope cost-grid engine and an **A* (A-Star) pathfinding algorithm** in JavaScript, and verify live that changing destinations, routing modes, or suit slope limits dynamically reshapes the route around steep no-go zones and updates the elevation chart.

## B. Existing Project Context
In `Pawstro – Mission Planner (1).html`:
- The SVG map coordinate space is `700 x 460`, with Habitat `#H` at `(165, 270)`, `Target A` at `(290, 218)`, `Target B` at `(405, 205)`, and `Target C` at `(540, 180)`.
- Steep / no-go hazard regions (`#L-steep`) are located around `(170,110)-(250,175)` and `(310,310)-(395,375)`.
- Currently, `#route` uses a static `d` path string that never changes geometry when targets, modes (`Safest`, `Fastest`, `Most science`), or the `Max slope` slider (`#r1`) change.

## C. Development Instructions
1. **Inspect Previous Phase Output:**
   - Verify all Phase 1 and Phase 2 functionality is intact.
2. **Build the Deterministic 2D Jezero DEM & Slope Grid (`70 x 46` grid cells mapping to `700 x 460` SVG space, `10x10` px per cell):**
   - Create a deterministic 2D elevation array `DEM[gy][gx]` representing Jezero Crater's floor (`-2540m`) sloping up toward the Western Delta fan (`-2420m`), with steep localized ridges/scarps corresponding to the `#L-steep` hazard zones and a moderate ridge (`~16–19 deg` slope) along the direct straight line between `H` and `Target B`/`C`, while a curved northern/southern corridor offers gentler slopes (`~8–11 deg`).
   - Compute `SLOPE[gy][gx]` in degrees for every grid cell.
   - Compute `SCI_SCORE[gy][gx]` representing mineral/science density near the carbonate/olivine deposits (`(260,160)` and `(470,150)`) and target sites.
3. **Reactive Steep / No-Go Zone Overlay (`#L-steep`):**
   - When the `Max slope` slider (`#r1`, `5` to `35 deg`) changes, dynamically update `#L-steep` by rendering SVG hazard cells/polygons for regions where `SLOPE[gy][gx] > maxSlope` (while preserving the signature hatched `url(#hat)` and `#ff6b8b` border style) so lowering `Max slope` visibly expands the red no-go zones on the map.
4. **Implement Slope-Aware 8-Directional A* Pathfinding Engine:**
   - Implement `findPathAStar(startPt, endPt, maxSlope, mode)` on the `70 x 46` grid:
     - Cells with `SLOPE[ny][nx] > maxSlope` receive a heavy impassable penalty (`1e5`) so A* automatically routes around them whenever a gentler detour exists.
     - **Mode `0` (`Safest`):** `cost = stepDist * (1 + (SLOPE[ny][nx] ** 2) * 0.12)` (strongly prefers flat crater floor, curving wide around ridges).
     - **Mode `1` (`Fastest`):** `cost = stepDist * (1 + SLOPE[ny][nx] * 0.02)` (takes the most direct path that stays under `maxSlope`).
     - **Mode `2` (`Most science`):** `cost = stepDist * (1 + SLOPE[ny][nx] * 0.05) * (1 - SCI_SCORE[ny][nx] * 0.35)` (curves through mineral-rich zones).
   - For `#dest.value === 'all'`, chain A* paths in optimal order (`H -> Target A -> Target B -> Target C`); for `'A'`, `'B'`, or `'C'`, run A* from `H` to `T[d]`.
   - Convert the A* grid path into a smooth SVG path string (`d="M165 270..."`) and set `#route.setAttribute('d', pathString)`.
5. **Compute Real Route Stats & Dynamic Elevation Profile (`#elev`):**
   - From the computed A* path cells, calculate:
     - `Distance` (`#sd` in `km`)
     - `Time` (`#st` in `min`, factoring in distance and slope traversal speed)
     - `Steepest` (`#ss` in `deg`, the peak `SLOPE[gy][gx]` along the path)
   - Sample `DEM[gy][gx]` along the A* path and draw the true elevation profile on `<canvas id="elev">`.
